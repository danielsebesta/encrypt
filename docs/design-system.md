# Design system

The main site (everything except the `/app` PWA) is built from one set of tokens and component classes in `src/styles/global.css` and a few Svelte 5 primitives in `src/components/ui/`. CSS in `global.css` is the source of truth; the primitives only emit those classes and wire up ARIA. `tests/design-system.test.ts` and `tests/design-rules.test.ts` enforce the rules below.

The `/app` PWA (`src/components/app/*`, `src/styles/app.css`) re-skins the same classes for iOS and Material and is out of scope here.

## Tokens

Colour tokens live in `:root` (light) and `html.dark` between the `palette:start` / `palette:end` markers. They are generated by `scripts/gen-palette.mjs` (`corepack pnpm run build:palette`), which also rewrites the `theme-color` metas in `Layout.astro` and the colours in `public/site.webmanifest` (`tests/palette.test.ts` fails if the tokens are edited by hand) and checked for WCAG AA by `scripts/contrast-check.mjs`.

| Token | Use |
| --- | --- |
| `--bg` | page background |
| `--surface`, `--surface-2` | panels, inputs, hover fills |
| `--line`, `--line-soft` | borders and dividers |
| `--control-line` | borders of inputs and secondary buttons (3:1 against the background) |
| `--text`, `--muted` | body text, secondary text (both 4.5:1) |
| `--accent`, `--accent-strong`, `--accent-weak`, `--accent-line`, `--on-accent` | the single green accent, its hover, tint, border and the text on it |
| `--warn`, `--warn-weak`, `--danger`, `--danger-weak` | warning and error text and tints |
| `--on-danger` | text on a filled danger button (alias of `--danger-weak`) |
| `--ring`, `--ring-danger` | 3 px focus ring of fields |
| `--shadow-float` | the only shadow: menus, popovers, modals, toasts (soft drop shadow only; the edge is the 1 px border) |
| `--call-*` | the always-dark call screen |

Every token has a Tailwind utility (`bg-surface`, `text-muted`, `border-line`, `text-on-danger`, …). Components and pages use only these. Colour literals (`#hex`, `rgb()`, `hsl()`, `oklch()`, Tailwind palette colours such as `bg-white`) are rejected by the guard test, except:

- `src/lib/qrColors.ts`: QR codes stay black on white in both themes. Their frames (`.ue-qr`, `.home-app__qr-code`, `.install-now__qr`) use `bg-white` in `global.css` for the same reason.
- Emoji skin-tone swatches and the white matte PhotoCipher puts behind transparent images before encoding. Each is listed with its reason in `COLOUR_ALLOW` in the test.
- The `theme-color` meta tags in `Layout.astro`, which the test pins to `--bg`.

When a canvas or library needs a colour, read the token at runtime with `getComputedStyle(document.documentElement).getPropertyValue('--accent')`.

## Typography

- **Allo** (`font-sans`) for all UI text. **Commit Mono** (`font-mono`, `<code>`, `.input--mono`, `.badge--mono`) for keys, hashes, sizes and other technical values.
- Sizes are Tailwind's: controls, labels, hints and menus use `text-sm` (14 px), body text `text-base` (16 px), page titles `.page-title` (fluid, 28–40 px). Nothing is set below `text-xs` (12 px); relative `em` sizes under 1em are floored with `max(0.75rem, …)`. The guard test checks both.
- Weights: 400 body, 500 controls and labels, 600 headings and titles.

## Spacing, radius, motion, layers

- Spacing is Tailwind's 4 px scale. Layout helpers: `.page`, `.page-head`, `.stack` (20 px gap), `.actions` (12 px gap, wraps), `.panel` (16 px, 24 px from `md`).
- Radius: `rounded-sm`/`rounded-md` = 6 px for controls, `rounded-lg` = 8 px for panels, menus and dialogs. `rounded-xs` = 4 px exists only for checkboxes. No pill or circle radii on controls (`design-rules.test.ts` rejects `999px`).
- Borders, not shadows. `--shadow-float` is reserved for floating layers.
- Motion: `--duration-fast` 100 ms (hover, press), `--duration-base` 180 ms (tab thumb, toasts, rings), `--duration-slow` 320 ms; `--ease-out` and `--ease-move`. Motion only gives feedback. `prefers-reduced-motion: reduce` turns transitions and animations off globally.
- Layers: `--z-nav` 10, `--z-menu` 20, `--z-toast` 40. Modals use the native top layer.

## Focus

Every focusable element gets the global `:focus-visible` outline (2 px `--accent`, 2 px offset). Fields replace it with a 3 px `--ring` box-shadow plus an accent border. In `forced-colors` mode fields, the dropzone and range inputs fall back to a `Highlight` outline.

## Buttons

One variant class, plus any modifiers:

| Class | Look |
| --- | --- |
| `btn` | primary: accent fill, `--on-accent` text, `--accent-strong` on hover |
| `btn-secondary` | `--surface` fill, `--control-line` border, `--surface-2` on hover |
| `btn-ghost` | transparent, `--muted` text, `--surface-2` and `--text` on hover |
| `btn-danger` | `--danger` fill, `--on-danger` text. Only for the confirming action of something destructive |
| `btn-link` | accent text, no padding, underline on hover, for inline "Read more" style actions |

| Modifier | Effect |
| --- | --- |
| (none) | 40 px tall, 16 px side padding |
| `btn-sm` | 32 px tall, 12 px side padding |
| `btn-icon` | square, no padding: 40×40 px, or 32×32 px with `btn-sm`. Needs `aria-label` |
| `btn-block` | full width |

All sizes use `text-sm` medium, `rounded-md`, an 8 px gap and a 1 px border (transparent where it is not visible). On `pointer: coarse` every button, small ones included, is at least 44 px tall and icon buttons 44 px wide. Icons inside buttons are 16 px; in default-size icon buttons they are 20 px. The CSS sets this, whatever `size` the `<Icon>` gets.

States:

- **Disabled** (`disabled` or `aria-disabled="true"`): filled variants turn `--surface-2` with `--muted` text, secondary keeps a `--line-soft` border, ghost and link drop to 50 % opacity. `<a>` buttons with `aria-disabled` stop taking clicks.
- **Busy** (`aria-busy="true"`): the label goes transparent and a 16 px spinner sits in its place, so the width does not change. Keep the button focusable and ignore clicks while busy (the `Button` primitive does both).
- **Pressed or checked** (`aria-pressed="true"` or `aria-checked="true"` on `btn-secondary` / `btn-ghost`): accent tint, `--accent-line` border, `--accent-strong` text. Use `aria-pressed` for toggles such as "show password" and toolbar tools, `aria-checked` when the button has a checkable role (`menuitemcheckbox`, `radio`).
- **Forced colors**: `ButtonText` borders, `Highlight` for pressed, `GrayText` for disabled.

Subtle destructive actions (remove, leave) are `btn-ghost` or `btn-secondary` with the `text-danger` utility. `btn-danger` is for the final confirm button.

```svelte
<button type="submit" class="btn btn-block">{t(dict, 'common.continue')}</button>
<button type="button" class="btn-secondary btn-sm" onclick={copy}>{t(dict, 'common.copy')}</button>
<button type="button" class="btn-ghost btn-sm btn-icon" aria-label={t(dict, 'common.close')} title={t(dict, 'common.close')}>
  <Icon name="x" />
</button>
<a class="btn-secondary" href="/install">{t(dict, 'nav.install')}</a>
```

Do not use `w-full` on buttons (use `btn-block`), combine two variants, or make a new `*-btn` class. The guard test rejects unknown `btn-*` classes, two variants in one class list, and `<button>` elements without a canonical class.

### `Button.svelte`

`src/components/ui/Button.svelte` renders the same classes. Use it in new code, especially for icon-only buttons, where `label` is required:

```svelte
<script lang="ts">
  import Button from '../ui/Button.svelte';
</script>

<Button variant="secondary" icon="copy" onclick={copy}>{t(dict, 'common.copy')}</Button>
<Button variant="ghost" size="sm" icon="x" label={t(dict, 'common.close')} onclick={close} />
<Button busy={saving} type="submit" block>{t(dict, 'common.save')}</Button>
<Button href="/share" variant="secondary">{t(dict, 'nav.share')}</Button>
```

Props: `variant` (`primary` | `secondary` | `ghost` | `danger` | `link`), `size` (`md` | `sm`), `block`, `icon`, `iconEnd`, `label`, `busy`, `pressed`, `disabled`, `href`, `type` (defaults to `button`), plus any native attribute. Without children it becomes an icon button and uses `label` as `aria-label` and `title`. A disabled link renders `<a role="link" aria-disabled="true">` without `href`. A caller's `aria-disabled="true"` is kept and, like `disabled` and `busy`, swallows clicks while the control stays focusable.

Legacy (`export let`) components that build class strings call `buttonClass({ variant, size, icon, block })` from `src/components/ui/button.ts`.

## Fields

| Class | Use |
| --- | --- |
| `.field` | grid wrapper: label, control, hint, error (6 px gap). `.field--fill` lets a textarea or dropzone fill the height |
| `.label` | `text-sm` medium. `.label__required` is the red asterisk |
| `.hint` | `text-sm` muted help text |
| `.input` | text inputs, `textarea.input`, `select.input`. Exactly 40 px tall (1 px border, 6 px vertical padding, 24 px line), 44 px on coarse pointers, the same as a default button. `textarea.input` starts at 128 px with 8 px padding. `.input--mono` for keys |
| `select.input` | chevron drawn with `--muted` gradients, so it follows the theme; `forced-colors` falls back to the native arrow |
| `.input` on `date`, `time`, `datetime-local` | native pickers; the focus ring also shows while focus is on the calendar indicator (`:focus-within`) |
| `.passphrase` | input plus inline icon buttons in one bordered box, 40 px tall like `.input` |
| `.check` | label row for a checkbox or switch (44 px tall) |
| `input[type=checkbox]`, `input[type=radio]` | 16 px custom controls. The check and indeterminate marks are an SVG mask painted with `--on-accent`, so no colour lives in a data URI |
| `input[type=checkbox][role=switch]` | 36×20 px switch |
| `input[type=range]` | 6 px track, 16 px thumb |
| `.dropzone` | dashed file drop area, also as `<button class="dropzone">` |
| `.choice-list` / `.choice` | radio cards |
| `.field-error` | error text under a control, with an alert icon |

Error contract: the control gets `aria-invalid="true"` and `aria-describedby` that includes the error id; the error is `<p id=… class="field-error">`. It carries no live role: on submit focus moves to the first invalid control (below) and the screen reader reads its error through `aria-describedby`, so a form with several errors does not fire several alerts at once. Only a form with a single password field whose error appears without moving focus (share, receive, room password) adds `role="alert"`. Box-style errors that are not tied to one control use `.status.status--error`.

On a failed submit, call `focusFirstInvalid(formEl)` from `src/lib/focusInvalid.ts`: it waits a tick for the error state to render, then focuses the first `[aria-invalid="true"]` control inside the root.

### `Field.svelte`

`src/components/ui/Field.svelte` generates the ids and wires `for`, `aria-describedby`, `aria-invalid`, `aria-errormessage` and `required`:

```svelte
<Field label={t(dict, 'chat.customRoomId')} hint={t(dict, 'chat.customRoomIdHint')} error={roomError} required>
  {#snippet children(control)}
    <input class="input" type="text" bind:value={roomId} {...control} />
  {/snippet}
</Field>
```

Props: `label`, `hint`, `error`, `required`, `hideLabel` (keeps the label for assistive tech only), `id` (otherwise generated), `class`, `aside` (snippet next to the label).

## Tabs and segmented control

`.tabs` + `.tab` is the underlined tab list; `.tabs--slide` turns it into a segmented control with a sliding `.tabs__thumb`. Always render them through `src/components/ui/Tabs.svelte`, which gives `role="tablist"`/`tab`/`tabpanel`, `aria-selected`, `aria-controls`, `aria-labelledby`, roving `tabindex` and ArrowLeft/ArrowRight/Home/End with automatic activation.

```svelte
<Tabs items={[{ id: 'encode', label: t(dict, 'x.encode') }, { id: 'decode', label: t(dict, 'x.decode') }]}
      value={mode} label={t(dict, 'x.h1')} idBase="photo" panelClass="grid gap-6" onchange={setMode}>
  …one persistent panel, labelled by the selected tab…
</Tabs>

<Tabs items={tabs} bind:value={active} label={t(dict, 'landing.try.label')} idBase="home" variant="segmented">
  {#snippet panel(id)}…one panel per tab, mounted on first visit…{/snippet}
</Tabs>
```

Props: `items` (`id`, `label`, optional `icon`), `value` (bindable), `label` (name of the tab list), `idBase`, `variant` (`line` | `segmented`), `class`, `panelClass`, `onchange`, and either `children` (one panel) or `panel` (one per tab).

Ids are `<idBase>-tab-<id>` and `<idBase>-panel` (single panel) or `<idBase>-panel-<id>` (per-tab panels). Tabs are 40 px tall, 44 px on coarse pointers.

## Toolbars and roving focus

A group of related buttons (editor tools, swatches, call controls, emoji categories) is one Tab stop. Put `role="toolbar"` and an `aria-label` on the wrapper and add the `roving` action from `src/components/ui/roving.ts`:

- ArrowLeft/ArrowRight wrap; without `columns` ArrowUp/ArrowDown do the same. Home and End jump to the ends.
- `use:roving={{ columns: 6 }}` lays the items out as a grid: ArrowUp/ArrowDown move one row and stop at the edges.
- The tab stop is the focused item, else the one with `aria-pressed`, `aria-checked` or `aria-current="true"`, else the last focused, else the first. It follows those attributes as they change.
- Disabled items are skipped. `selector` (default `button`) narrows which descendants take part.

```svelte
<div class="wb-pill" role="toolbar" aria-label={t(dict, 'whiteboard.toolbar')} use:roving>
  {#each TOOLS as item}
    <button type="button" class="btn-ghost btn-icon" aria-pressed={tool === item.id} aria-label={label(item)}>…</button>
  {/each}
</div>
```

Segmented sets inside a labelled `role="group"` (the whiteboard style panel) use the same action. Radio groups with arrow-to-select semantics (`role="radiogroup"`) and tab lists (`Tabs.svelte`) keep their own handlers.

## Menus and popovers

Every floating layer has the same surface: `--surface` fill, 1 px `--line` border, 8 px radius and `--shadow-float`. `.popover` is that surface on its own (profile card, emoji picker, whiteboard chat and people panels); `.menu` adds the menu layout on top of it. The navigation dropdowns, the burger panel, `.modal` and `.toast` use the same values. Do not give a floating layer a different fill or border; the call screen (`--call-*` tokens) and the `/app` skins are the only exceptions.

`.menu` (popover surface, 8 px radius), `.menu--open`, `.menu--end` (right-aligned), `.menu__item` (40 px, 44 px coarse, `text-sm` medium), `.menu__item--danger`, `.menu__sep`, `.menu-anchor` (positioning wrapper). Items with `aria-checked="true"` are toggles.

Keyboard and focus come from the `menu` action in `src/components/ui/menu.ts`: ArrowUp/ArrowDown wrap, Home/End, Escape closes and returns focus to the trigger, Tab closes, a pointer press outside closes, and the first item takes focus on open (`autofocus: 'last'` for the last item, `false` when the caller already moves focus). The trigger carries `aria-haspopup="menu"`, `aria-expanded` and `aria-controls`; on `Menu.svelte` ArrowDown/ArrowUp on the trigger open the menu on the first/last item.

```svelte
<Menu label={t(dict, 'chat.roomMenu')}>
  {#snippet children(close)}
    <button type="button" role="menuitem" class="menu__item" onclick={() => { close(); copyLink(); }}>
      <Icon name="link" />{t(dict, 'chat.copyLink')}
    </button>
  {/snippet}
</Menu>
```

Props of `Menu.svelte`: `label` (required, names the menu and the icon-only trigger), `icon` (default `ellipsis-vertical`), `text` (turns the trigger into a labelled button), `variant` (default `ghost`), `size` (default `sm`), `align` (`start` | `end`, default `end`), `open` (bindable), `class`.

The site navigation dropdowns in `Layout.astro` are disclosure navigation (links, driven by `public/ui.js`), not ARIA menus, and share only the `.menu` styling. The current page (`aria-current="page"`) and the current language (`aria-current="true"`) get the `--surface-2` fill; in `forced-colors` they are underlined. Under 1024 px the dropdowns open inline in the burger panel, indented under a 1 px guide line.

## Dialogs

`src/components/Modal.svelte` is the only dialog: native `<dialog>` opened with `showModal()` (focus trap and inert background from the browser), focus on `initialFocus`, `[autofocus]` or the first field, focus returned to the opener, Escape, close button and backdrop click when `dismissible`, nothing closes while `busy`, `role="alertdialog"` for confirmations, and a bottom sheet under 640 px with full-width stacked actions. Ids come from `$props.id()`. Styles are the `.modal*` classes in `global.css`.

```svelte
<Modal bind:open dict={dict} title={t(dict, 'chat.burnTitle')} description={t(dict, 'chat.burnText')} icon="flame" tone="danger" role="alertdialog" onsubmit={burn}>
  {#snippet actions()}
    <button type="submit" class="btn-danger">{t(dict, 'chat.burnConfirmYes')}</button>
    <button type="button" class="btn-secondary" onclick={() => (open = false)}>{t(dict, 'common.cancel')}</button>
  {/snippet}
</Modal>
```

## Status, alerts, progress, toasts

- `.status` box (`--surface-2`), with `.status--ok`, `.status--warn`, `.status--error` (alert icon) and `.status--busy` (spinner). In `forced-colors` the box gets a 1 px `CanvasText` outline and the alert icon is painted `CanvasText`, since the tints disappear there. Use `role="status"` for progress and results that can wait, `role="alert"` only for errors the user must act on now.
- `src/components/tools/ToolStatus.svelte` renders that box for tools: `<ToolStatus tone="error" id="x-error">…</ToolStatus>` with `tone` `info` | `ok` | `warn` | `error` | `busy`, and picks `role="alert"` for errors, `role="status"` otherwise.
- `ProgressPulse.svelte` renders the `.status__ring` progress card. `.progress` styles a native `<progress>` bar (8 px, accent fill).
- `.spinner` is the 16 px inline spinner, the same one busy buttons show.
- `.toast` is the one floating notification (fixed, bottom centre, above the safe area, `--shadow-float`, 180 ms entrance). `.toast--contained` positions it absolutely inside the nearest positioned container instead (call screen), `--toast-offset` (default 1 rem) above that container's bottom edge and at most 26 rem wide. Render it with `role="status"`, or `role="alert"` for a failure.
- `.output` (`.output--ok`, `.output--scroll`) shows results in monospace. `src/components/tools/ToolResult.svelte` wraps one result: `.field` with an `.output-head` row (label plus `CopyButton` when `copy` and `text` are set) and an `<output>` labelled by it. Props: `dict`, `id`, `label`, `text`, `copy` (default true), `prose` (wrap words instead of breaking anywhere), `class`, an `output` snippet that replaces the `<output>`, and `children` rendered below it.

## Badges, chips, cards, empty states, disclosures

- `.badge`: 20 px, `text-xs` medium, 6 px radius, neutral. `.badge--accent`, `.badge--warn`, `.badge--danger`, `.badge--mono`. Not interactive.
- `.chip`: 32 px interactive token (filters, reactions, choices) on a `<button>`. Selection is `aria-pressed="true"` or `aria-checked="true"` with the accent tint.
- `.panel`: the card. 8 px radius, `--line` border, `--surface` fill, 16/24 px padding. `.panel--flush` drops the padding and clips the content, for lists and media that run edge to edge; focus rings inside it are drawn inset (`outline-offset: -2px`) so the clip does not cut them.
- `.link`: inline text link in prose (`--accent-strong`, underline that darkens on hover). Add `text-current` inside a tinted `.status`.
- `.icon-tile`: 40 px square, 6 px radius, `--surface-2` fill, `--line` border, muted icon; leads a card or row. `.icon-tile--accent` uses the accent tint to mark the emphasised item. Decorative: an `<Icon>` without a label is already `aria-hidden`.
- `.empty` + `.empty__icon` + `.empty__title`: centred empty state, muted text.
- `details.more`: disclosure with a rotating chevron and `.more__body`; the summary is 40 px tall, 44 px on coarse pointers. `ToolAbout.astro` renders the expandable "How it works" section with a `btn-link` toggle that keeps `aria-expanded` in sync.
- Tooltips: no custom component. Icon-only buttons repeat their `aria-label` in `title`.

## Icons

`<Icon name="…" />` (`Icon.astro`, `Icon.svelte`), 16 or 20 px, Tabler filled. Names live in `src/lib/iconManifest.ts`. See `AGENTS.md`.

## Do and don't

- Do reuse a class from this page. Don't add a component-scoped look-alike (`.foo-btn`, `.foo-pill`, `.foo-card`).
- Do use tokens. Don't write colour literals, `bg-white`, or opacity hacks for disabled text.
- Do give every icon-only control an `aria-label`. Don't rely on `title` alone.
- Do keep 40 px controls (44 px on touch). Don't shrink buttons below `btn-sm` or text below 12 px.
- Do use `aria-pressed` / `aria-checked` / `aria-expanded` for state. Don't signal state with colour alone.
- Do respect `prefers-reduced-motion`. Don't animate for decoration.
